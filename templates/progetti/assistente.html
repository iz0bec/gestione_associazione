Il gestionale non contiene IA. Il connettore MCP permette a un assistente scelto da voi (un modello locale con Ollama, o servizi come Claude) di leggere idee, bandi con i requisiti, progetti, finalità e criteri, per aiutarvi a confrontare e motivare le valutazioni. Le decisioni restano vostre.

  • L'assistente vede solo ciò che vedete voi: il token vale con i vostri permessi.
  • Nessun dato personale dei soci: solo numeri aggregati; le persone fisiche compaiono come «persona (riservato)».
  • Sola lettura; i commenti firmati «[Assistente]» solo se ammessi dall'amministratore e dal token.
  • Ogni chiamata è nel registro attività. Con un modello locale (Ollama) i dati restano nella vostra rete; con un servizio esterno vanno a quel servizio: sceglietelo secondo le regole dell'associazione.

Ollama senza interfaccia web (consigliato: i dati restano in casa)

Ollama non collega da solo i server MCP: lo fa ollama-mcp-bridge, un ponte che si mette davanti a Ollama e aggiunge gli strumenti del gestionale alle chat (/api/chat). Sul computer dove gira Ollama (serve Python con uv, oppure pip install ollama-mcp-bridge):

  1. un file mcp-config.json (il token resta fuori dal file, in una variabile d'ambiente): 
    { "mcpServers": { "gestionale": {
    "url": "{{ indirizzo }}",
    "headers": { "Authorization": "Bearer ${env:GA_MCP_TOKEN}" } } } }
  2. avviare il ponte, che parla con Ollama e ascolta su un'altra porta: 
    export GA_MCP_TOKEN='{% if nuovo %}{{ nuovo }}{% else %}TOKEN{% endif %}'
uvx ollama-mcp-bridge --config mcp-config.json --ollama-url http://127.0.0.1:11434 --port 8001
  3. usare il ponte al posto di Ollama, con un modello locale che supporta gli strumenti (per esempio qwen3:8b, llama3.1, gpt-oss:20b; non i modelli :cloud, che manderebbero i dati fuori): 
    curl http://127.0.0.1:8001/api/chat -d '{"model": "qwen3:8b", "stream": false,
  "messages": [{"role": "user", "content": "Quali bandi ci sono da vagliare?"}]}'

Opzioni e valori predefiniti cambiano fra le versioni del ponte: in caso di dubbio uvx ollama-mcp-bridge --help. Se il gestionale usa un certificato della CA interna, il ponte deve fidarsene (per esempio export SSL_CERT_FILE=/percorso/ca-interna.pem).

Ollama con Open WebUI

In Open WebUI (versione 0.6.31 o successiva): Impostazioni di amministrazione → External Tools → aggiungi, tipo MCP (Streamable HTTP) (non OpenAPI), URL qui sopra, autenticazione Bearer con il token nel campo Key.

Claude Code

claude mcp add --transport http gestionale {{ indirizzo }} --header "Authorization: Bearer {% if nuovo %}{{ nuovo }}{% else %}TOKEN{% endif %}"

Claude Desktop

Nel file claude_desktop_config.json (serve Node.js):

{ "mcpServers": { "gestionale": { "command": "npx",
  "args": ["mcp-remote", "{{ indirizzo }}", "--header", "Authorization: Bearer {% if nuovo %}{{ nuovo }}{% else %}TOKEN{% endif %}"] } } }

Il server del client deve raggiungere il gestionale in HTTPS con un certificato che riconosce (in rete interna: la CA interna installata sul client).
